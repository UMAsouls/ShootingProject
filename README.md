# Shooting BaseBall

攻撃側と防御側に分かれて戦う、2人対戦型のシューティングゲームです。

攻撃側は弾を撃って相手の陣地を攻撃し、防御側はレーザーソードで飛んできた弾を弾き返します。
攻撃と防御で異なる操作を行いながら、相手との駆け引きを楽しめるゲームとして制作しました。

## ゲーム内容

2人のプレイヤーが**攻撃側**と**防御側**に分かれて対戦します。

### 攻撃側

弾を発射して、防御側の陣地を攻撃します。
制限時間内に相手の陣地を破壊できれば勝利です。

### 防御側

レーザーソードを使って、攻撃側が発射した弾を弾き返します。
制限時間が終了するまで陣地を守り切れば勝利です。

攻撃側は防御をかいくぐって陣地を攻撃し、防御側は飛んでくる弾を見極めて弾き返すという、**役割ごとに異なる操作と駆け引き**を楽しめるゲームになっています。

## 操作方法

### 攻撃側

| キー              | 操作        |
| --------------- | --------- |
| `W` `A` `S` `D` | 移動        |
| `X`             | ストレート弾を発射 |
| `C`             | 左カーブ弾を発射  |
| `V`             | 右カーブ弾を発射  |
| `B`             | 変速弾を発射    |

### 防御側

| キー              | 操作  |
| --------------- | --- |
| `I` `K` `J` `L` | 移動  |
| `Enter`         | 左打ち |
| `Right Shift`   | 右打ち |

## 工夫したところ

### Unityを参考にしたゲーム開発フレームワークを自作

Pygameを用いたチーム開発を効率化するため、ゲーム制作に必要な共通処理をまとめた独自フレームワークを作成しました。

ゲーム内のオブジェクトを表す `GameObject` クラスを用意し、各ゲームオブジェクトはこれを継承して実装します。
`GameObject` には `Start()` と `Update()` を定義し、Unityと同じように初期化処理と毎フレームの更新処理を記述できる構造にしました。

また、`GameObject` はPygameの画像を扱う `Surface` と、矩形領域を扱う `Rect` を保持しており、フレームワーク側で描画や当たり判定に利用できるようにしています。

他のメンバーはフレームワーク内部のゲームループやオブジェクト管理を意識することなく、`GameObject` を継承して `Start()` と `Update()` を実装することでゲームロジックを作成できます。

### JSONによるシーン構築

ゲーム内のシーンをJSONファイルから構築できる仕組みを作成しました。

JSON上で使用する `GameObject` のクラスと各変数の値を指定することで、ソースコードを直接変更せずにオブジェクトの配置や初期パラメータを設定できます。

また、指定されたオブジェクトクラスを自動的に読み込む仕組みを用意し、シーンファイルからゲームオブジェクトを生成できるようにしました。

### ゲーム制作に必要な共通機能の提供

メンバーがゲーム固有のロジック制作に集中できるよう、以下のような汎用機能もフレームワーク側に実装しました。

* ベクトル計算を行う `Vector` クラス
* BGM・効果音などを制御する `Music` クラス
* Pygameの入力処理を扱いやすくする `Key` クラス
* ゲームオブジェクトの生成・更新を行うゲームループ

これらの共通処理をフレームワーク側に集約することで、ゲーム側のコードからPygame固有の処理を減らし、ゲームロジックの実装に集中できるようにしました。

### チーム開発を意識した設計

3人で並行して開発することを想定し、各メンバーがフレームワーク内部の実装を理解していなくてもゲーム制作を進められる設計を目指しました。

ゲーム側では主に `GameObject` を継承したクラスを作成し、用意されたインターフェースを通して処理を記述する構造とすることで、共通処理とゲーム固有処理の責務を分離しました。
